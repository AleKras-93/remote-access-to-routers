# Headscale на Keenetic MIPSel

Проверено на роутере `moy-router-1011`: Entware `mipsel-3.4`, Tailscale и Headscale. Пользователь подтвердил работу веб-интерфейса Keenetic, XKeenUI и SSH из сети Headscale. Проверка после перезагрузки пока не проводилась.

## Подтверждённая конфигурация

| Параметр | Значение |
|---|---|
| Headscale | `https://headscale.tuttamdns.ru` |
| Пользователь Headscale | `alekras` |
| Имя устройства | `moy-router-1011` |
| Tailscale IPv4 | `100.64.0.9` |
| LAN-адрес роутера | `192.168.3.1` |
| Keenetic | `http://moy-router-1011.tailnet.tuttamdns.ru:8081/` |
| XKeenUI | `http://100.64.0.9:1000` |
| SSH Entware | `100.64.0.9:222` |

Локальный веб-сервер слушал `192.168.3.1:80`, но не адрес Tailscale. Поэтому для доступа к штатной панели использован Tailscale Serve, направленный на LAN-адрес.

## Совместимость и установка

На проверенном устройстве `uname -m` вернул `mips`, а `opkg print-architecture` показал `mipsel-3.4` и `mipsel-3.4_kn`. В установленном Entware присутствует `/dev/net/tun`. `free -m` вывел значения, соответствующие примерно 512 МБ ОЗУ; на BusyBox следует проверять единицы вывода, а не считать их автоматически мегабайтами. На `/opt` было достаточно места.

Пакет `tailscale` версии `1.104.4-1` установлен из настроенного репозитория Entware `mipselsf-k3.4`:

```sh
opkg update
opkg install tailscale
/opt/etc/init.d/S06tailscaled start
/opt/etc/init.d/S06tailscaled status
```

Скрипт сообщил `alive`; команду `enable` он не поддерживает. Автозапуск необходимо проверять после перезагрузки конкретного устройства. TailScaleKeen ориентирован на ARM64; здесь использован пакет Entware без этой панели. Наличие пакета не гарантирует совместимость каждой модели.

На этом роутере `opkg update` завершился успешно, но `opkg list | grep '^tailscale '` выдавал `Segmentation fault`. Установка по точному имени при этом прошла. Причина падения списка не установлена; не считать проблему решённой и не выполнять массовое обновление для её обхода.

## Подключение нового роутера

### Установка и регистрация скриптом

Скрипт `setup-headscale.sh` автоматизирует описанные ниже шаги для Entware MIPSel. Потребуются доступ root по SSH, смонтированный `/opt`, устройство `/dev/net/tun`, доступ к репозиторию Entware и серверу Headscale. Подготовьте уникальное имя роутера и IPv4 домашнего интерфейса `br0`. Скрипт рассчитан на штатную веб-панель с HTTP на порту 80.

Скопируйте скрипт из проекта в `/tmp/setup-headscale.sh` на роутере, например через SFTP в Termius. В SSH Entware выполните команду, заменив пример имени и адреса своими значениями.

```sh
sh /tmp/setup-headscale.sh keenetic-ofis 192.168.3.1
```

Скрипт проверяет архитектуру и LAN-адрес, устанавливает пакет по имени и запускает клиент. При первом подключении откройте выведенную им ссылку. На VPS выполните команду регистрации со страницы от имени `sudo`, указав `--user alekras`. Оставьте сессию роутера открытой. После регистрации скрипт настроит Serve, если его конфигурация пуста, и покажет адреса для проверки.

**Для серии роутеров** можно заранее выпустить отдельный одноразовый ключ на каждый роутер. На VPS в Headscale 0.29.7 проверьте числовой ID пользователя и выпустите ключ на 15 минут (в примере ID пользователя `alekras` равен 1).

```sh
sudo headscale users list
sudo headscale preauthkeys create --user 1 --expiration 15m
```

На роутере сохраните только значение ключа в файле, доступном root (например, в файле, созданном `mktemp` в `/tmp`, с правами `600`). Передайте путь третьим аргументом. После успешной регистрации удалите файл ключа. Храните ключ отдельно от Git.

```sh
sh /tmp/setup-headscale.sh keenetic-ofis 192.168.3.1 /tmp/ИМЯ_ФАЙЛА_КЛЮЧА
```

Проверьте с телефона или ПК в Headscale ссылку панели из Serve, XKeenUI на порту `1000` и SSH Entware на настроенном порту (на проверенном роутере `222`). При повторном запуске скрипт сверяет имя и сервер активного клиента и показывает существующие настройки Serve.

### Ручная установка и проверка регистрации

Выполняйте на роутере, подставив уникальное имя вместо `router-name`:

```sh
/opt/bin/tailscale up \
  --login-server=https://headscale.tuttamdns.ru \
  --hostname=router-name \
  --accept-dns=false
```

Откройте выданную ссылку и выполните показанную ей команду **на VPS**, указав пользователя `alekras` и `sudo`. Регистрационные ключи не сохраняйте в документации. На роутере проверьте:

```sh
/opt/bin/tailscale status
/opt/bin/tailscale ip -4
```

Перед настройкой Serve проверьте существующую конфигурацию:

```sh
/opt/bin/tailscale serve status
```

Если конфигурации нет, для проверенного роутера применена команда:

```sh
/opt/bin/tailscale serve --bg --http=8081 http://192.168.3.1:80
```

Для других роутеров укажите их фактический LAN-адрес и порт. Открывайте имя, которое выведет Serve: прямое обращение к IP с портом `8081` может вернуть `404`. Не заменяйте существующую конфигурацию Serve без проверки.

## Оставшаяся проверка

При наличии независимого доступа перезагрузить роутер, дождаться подключения и проверить все три сервиса из другой сети. Убедиться, что `S06tailscaled status` сообщает `alive`, а `tailscale serve status` сохраняет маршрут. Учитывать, что правила доступа и особенности прошивки могут отличаться на других моделях.
