# Управление Headscale через Headplane

Состояние на 25 ноября 2026 года: Headscale 0.29.7 работает на VPS как служба systemd. Headplane 0.8.2 запущена в Docker рядом с ним; Headscale в контейнер не переносился. Caddy направляет запросы к панели на локальный порт 3000, а остальные запросы к Headscale — на локальный порт 8080.

Панель администратора: https://headscale.tuttamdns.ru/admin/ . Панель TorrServer работает отдельно: маршруты Caddy зависят от имени хоста. При изменении конфигурации Caddy проверяйте оба сервиса.

## Вход и управление

Для входа в Headplane можно создать ключ API **на VPS**:

```sh
sudo headscale apikeys create --expiration 90d
```

Ключ показывается только при создании и даёт административный доступ. Введите его в панели; не сохраняйте его в Git и не передавайте в чат. После истечения срока создайте новый ключ.

В панели можно создавать пользователей Headscale и управлять устройствами. Создан пользователь `routers`; существующие роутеры пока принадлежат `alekras`. Конфигурация Headscale подключена к контейнеру только для чтения: её изменение через панель не настроено.

На VPS проверить службы можно так:

```sh
systemctl is-active headscale caddy torrserver-panel torrserver
sudo docker ps --filter name=headplane
```

## Перенос устройств

В Headscale 0.29.7 штатной смены владельца существующего устройства через Headplane нет. По [тестам Headscale 0.29.7](https://github.com/juanfont/headscale/blob/v0.29.7/integration/auth_key_test.go), повторная регистрация устройства под другим пользователем создаёт новую запись, а не переносит прежнюю. IP-адрес и имя могут измениться; доступ, маршруты и правила ACL необходимо проверить заново.

Не удаляйте старую запись заранее и не переносите устройства массово. Сначала выберите один тестовый роутер с проверенным независимым доступом помимо Headscale, зафиксируйте его адреса, настройки и маршруты, сделайте свежую копию базы и проверьте восстановление. Затем проверяйте доступ к панели роутера, XKeenUI и SSH через новую запись. Само наличие копии базы не гарантирует восстановления состояния клиента.

## Резервная копия

База Headscale — SQLite: `/var/lib/headscale/db.sqlite`. Она может использовать WAL, поэтому при работающей службе не копируйте только файл базы обычной командой `cp`. Используйте механизм SQLite Backup API или проверенный снимок; проверьте копию командой `PRAGMA integrity_check`. Также сохраняйте `/etc/headscale`, прочие необходимые файлы `/var/lib/headscale` и конфигурацию Caddy, включая подключаемые файлы и сертификаты. Настройки TorrServer могут находиться отдельно.

До установки панели была создана копия базы и конфигураций Headscale и Caddy в `/root/headscale-backup-20261125-133152`. После создания пользователя `routers` создана свежая копия базы `/root/headscale-before-router-migration-20261125-135926.sqlite`; обе копии базы прошли проверку целостности. Восстановление из них пока не проверялось. Копия на том же VPS не защищает от потери диска: храните дополнительную копию вне сервера в защищённом виде.

Резервные копии могут содержать приватные ключи, токены и другие секреты. Не публикуйте их в GitHub. При восстановлении учитывайте изменения после даты копии и состояние клиентов: откат всей базы может отменить более поздние регистрации и настройки.
