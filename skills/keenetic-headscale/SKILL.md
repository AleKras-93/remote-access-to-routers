# Keenetic и Headscale

Используй навык при подключении роутера Keenetic или совместимого устройства с Entware к Headscale, а также при диагностике доступа к панели Keenetic, XKeenUI и SSH. Уточняй архитектуру, модель, LAN-адрес, локальный SSH-порт и существующие настройки. Не запрашивай пароли, приватные ключи и регистрационные токены в чат.

Для сети пользователя контроллер `https://headscale.tuttamdns.ru`, пользователь `alekras`, DNS-домен узлов `tailnet.tuttamdns.ru`. Используй эти значения, если пользователь не указал другие. Регистрацию выполняют на VPS через `sudo headscale auth register --auth-id <ключ_со_страницы> --user alekras`.

## Выбор клиента

- На ARM64 с Entware `aarch64-3.10` можно использовать TailScaleKeen, если прошивка поддерживает OpkgTun. Установщик и требования проверяй в актуальной документации проекта: https://github.com/Zhanchuraev/TailScaleKeen
- На MIPSel пакет Entware `tailscale` работал на `moy-router-1011`. Его SSH Entware использует порт 222. Скрипт проекта `setup-headscale.sh` и `Headscale_Keenetic_MIPSel.md` содержат процедуру, но совместимость нового устройства нужно проверять отдельно.
- На прошитом N6 AX1800 KN-2311 с KeeneticOS 5.0.7 Entware `mipsel-3.4` и TUN пакет Tailscale 1.104.4 подключился как `artur-yuvelir-roditeli`. После повторной регистрации узел получил IP `100.64.0.18`. Порт SSH Entware `222` доступен через Tailscale Serve на внешнем порту `2222` с проксированием на `192.168.1.1:222`; пользователь подтвердил подключение по адресу `100.64.0.18:2222`. При повторной регистрации проверяй новый IP и восстанавливай Serve-конфигурацию, если она была сброшена. Панель Keenetic работает через Serve `:8081` и Zashboard через `:8083` → `192.168.1.1:9090`; работа после перезагрузки не подтверждена.
- На этом N6 `/opt/bin/grep` завершался с `Bus error`, а `/opt/bin/busybox grep` работал. Причина ошибки не установлена; не объявляй её устранённой и не считай такой сбой общим свойством всех MIPSel.
- `/dev/net/tun` подтверждает доступность Linux TUN, но не поддержку типа интерфейса KeeneticOS `OpkgTun`. Команда `ndmc -c "interface OpkgTun0"` может изменить конфигурацию. Сообщение `unsupported interface type: "OpkgTun"` подтверждает, что этот тип недоступен в текущей прошивке.

## Прошивка без OpkgTun

На C960 KN-1012 с KeeneticOS 4.3.2 установщик TailScaleKeen остановился на создании OpkgTun0, оставив официальный клиент `/opt/bin/tailscale`, демон `/opt/bin/tailscaled` и службу `/opt/etc/init.d/S06tailscaled`. Доступ через Headscale заработал с Linux-интерфейсом `tailscale0`.

Перед изменениями проверь существующий пакет, процессы и содержимое init-скрипта, чтобы не запустить второй демон и не затронуть работающую установку. Если служба оставлена установщиком и содержит `--tun=opkgtun0`, сохрани её копию **вне** `/opt/etc/init.d/`, замени только этот параметр на `--tun=tailscale0`, затем запусти и проверь службу. Резервную копию не называй `S*` в каталоге автозапуска.

Зарегистрируй клиент с уникальным именем и `--accept-dns=false`, если требуется сохранить DNS роутера. Пример запуска на роутере:

```sh
/opt/bin/tailscale up --login-server=https://headscale.tuttamdns.ru --hostname=nesterov-c960 --accept-dns=false
```

На проверенном устройстве имя `nesterov-c960`, адрес Tailscale `100.64.0.12`, LAN `192.168.1.1`. Все три сервиса работали до перезагрузки. Автозапуск после перезагрузки ещё не проверен.

## Доступ к сервисам

XKeenUI обычно доступен по IP Tailscale на порту 1000. Для SSH используй фактический порт устройства, который может быть 22 или 222. Если штатный веб-интерфейс не слушает адрес Tailscale, проверь существующий `tailscale serve status`. При пустой конфигурации можно направить Serve на LAN-адрес роутера, например:

```sh
/opt/bin/tailscale serve --bg --http=8081 http://192.168.1.1:80
```

Открывай имя, выданное Serve, например `http://nesterov-c960.tailnet.tuttamdns.ru:8081/`; обращение по IP может вернуть 404. Существующий Serve не перезаписывай без проверки. Проверь все три сервиса из другой сети и после перезагрузки, когда есть независимый доступ.

На оригинальном Hopper KN-3811 с KeeneticOS 5.0.11 и Entware Tailscale 1.104.4 узел `ukhanov` получил `100.64.0.14`. Прямое Tailscale-соединение работало, но клиент сообщил об ошибке добавления правила в `ts-input`, а SSH и XKeenUI, слушавшие `0.0.0.0`, напрямую не отвечали. Причина ошибки firewall не установлена. Tailscale Serve обеспечил доступ к сервисам через LAN-адрес роутера:

```sh
/opt/bin/tailscale serve --bg --http=8081 http://192.168.1.1:80
/opt/bin/tailscale serve --bg --http=8082 http://192.168.1.1:1000
/opt/bin/tailscale serve --bg --tcp=2222 tcp://192.168.1.1:22
/opt/bin/tailscale serve --bg --http=8083 http://192.168.1.1:9090
/opt/bin/tailscale serve status
```

Применяй эти команды только с фактическими LAN-адресом и портами устройства, проверив занятость и существующий Serve. Для `ukhanov` страницы Keenetic (`:8081`) и XKeenUI (`:8082`) ответили HTTP 200, SSH на `100.64.0.14:2222` ответил на рукопожатие, а пользователь подтвердил работу Zashboard. Вход в SSH с учётными данными и восстановление после перезагрузки отдельно не подтверждены. Правило firewall этим способом не исправлено.

Zashboard открывается по имени Serve с путём `/ui`, например `http://ukhanov.tailnet.tuttamdns.ru:8083/ui`. На экране настройки подключения укажи HTTP, этот же домен и порт `8083`; дополнительный путь оставь пустым. Пароль — значение `secret` Mihomo, если оно задано. Сам секрет в чат или репозиторий не помещай. Пользователь подтвердил подключение с этими настройками.

Если `curl` после частичного обновления Entware не запускается, проверь `opkg status curl libcurl libnghttp2` и `curl --version`. На C960 `curl` 8.23 обновился при старом `libcurl` 8.12 и отсутствующей `libnghttp2`; установка `libnghttp2` и обновление `libcurl` исправили запуск. Выбирай исправление по фактическим зависимостям, не запускай массовое обновление ради этого случая.
